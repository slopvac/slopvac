# Slopvac 3.0 profile and tier mapping

Status: contract for 3.0. Bead `slopvac-8l4.2.10`. Plan: [slopvac-3.md](../design/slopvac-3.md). Config: `slopvac-8l4.2.5`. Plugins and styles: [plugins.md](plugins.md). Compatibility matrix: [compat/](compat/).

A 2.x profile cannot be a threshold plus a severity shift. `profiles.py` sets a severity, a density budget and a weight for each category. It also sets per-rule defaults, and each rule YAML file carries a `tiers` entry per profile. The dispositions are not monotonic. `orwell-voice` is a warning at strict and an error at normal, and `meta` is an error at every profile. 3.0 removes `tiers` and gives a profile two jobs: gate thresholds and a severity shift. This document says where the rest goes.

## 1. Mapping

| 2.x | 3.0 |
| --- | --- |
| Profile name in `profile` | The same name. The 3.0 profile sets the thresholds in section 2. Its `severity_shift` is 0. |
| Category severity, budget and weight in `profile_defaults` | The `categories` table of the style `core:legacy-<profile>`. |
| Per-rule defaults in `profile_rule_defaults` | A `rules` entry in that style. |
| Rule `tiers`: `enforced` | No entry. The rule reports at its level. |
| Rule `tiers`: `advisory` | A `rules` entry at `suggestion` when the category level is higher. |
| Rule `tiers`: `excluded` | A `rules` entry at `off`, always, even inside a category that is already off. |
| Judgement rule `tiers` | A `rules` entry for every judgement rule: `enforced` is `error`, `advisory` is `suggestion`, `excluded` is `off`. |
| `thresholds` of the profile | The profile thresholds in section 2. |
| Genre to profile (`genres.py`) | The `profile` field of the genre file (plugins.md section 4). |

The styles are generated by `scripts/contract/profile_mapping.py` from the 2.x engine and live in [`compat/profiles/`](compat/profiles/). They cover the whole catalogue: the checked rules and the judgement rules. The numbers per profile are in [`compat/profiles/mapping.json`](compat/profiles/mapping.json), with the per-rule defaults of each profile.

The styles name only categories that own at least one rule. The 2.x profile tables also list categories that own none: `meta`, `orwell-voice`, `prose-density` and `ste-vocabulary`. Nothing in them could report, so the styles leave them out. `slopvac migrate` drops each such category, at the top level and in every override, and prints a `migrate-category-removed` line that names it. The catalogue includes `ste-words.spelling`, which 2.x generates from the locale. The relaxed style turns it off.

The styles set the four vocabulary rules (`ste-verbs.verb-form-not-listed`, `ste-words.verb-or-adjective-form-not-permitted`, `ste-words.word-outside-controlled-vocabulary` and `ste-words.word-used-in-wrong-part-of-speech`) to `off`. Vocabulary checking is opt-in: 2.x ran it only when `vocabulary.path` was set, and a style cannot set a word blocklist. Each profile has a companion style, `core:legacy-strict-vocabulary`, `core:legacy-normal-vocabulary` or `core:legacy-relaxed-vocabulary`, that sets only those four rules to the level the 2.x profile gave them: `error` under strict, `suggestion` under normal and `off` under relaxed. The generator writes the companions from the same data as the styles. When `slopvac migrate --preserve-behavior` moves a top-level `vocabulary.path` into `terms.blocklists`, it lists the companion after `core:legacy-<profile>` in `styles` and writes no vocabulary rule in any config layer. The levels then sit in the style layer, where 2.x kept its profile defaults, so authored rules, category levels, floors and later overrides resolve as they did in 2.x. An override that changes the path keeps the same levels.

### Removed rules

The file lists five 2.x rules that 3.0 drops. [`compat/removed-rules.toml`](compat/removed-rules.toml) is the source of truth for the list: each entry has the rule id, a reason and the decision behind it. `slopvac migrate` drops every config entry and suppression directive that names one of them, and a test checks that each id is a 2.x rule.

### Migrate decisions

- `--preserve-behavior` writes `core:legacy-<profile>` as the style, as step E1 says. 2.x used `legacy-<profile>`. The new name is intended.
- A directive id that `migrate` cannot map reuses the `config-legacy-dropped` notice.

### Judgement rules

A judgement rule produces no finding. In 2.x its tier decided whether the review checklist lists it and whether a failure blocks the verdict. Its category level and every `[rules]` entry were ignored. The level of a judgement rule in 3.0 is the review level: `error` blocks the review verdict, `suggestion` reports without blocking, and `off` skips the rule. Only a `rules` entry sets it. A `categories` entry does not.

The checklist for a genre lists the judgement rules whose category recommends the genre and whose level is not `off`. This equals the 2.x selection at every profile.

## 2. Thresholds

A 3.0 profile sets these thresholds, which equal the 2.x values. An absent threshold is unset and its gate does not run.

| Threshold | strict | normal | relaxed |
| --- | --- | --- | --- |
| `max_total_per_100_words` | 1.5 | 3.0 | 8.0 |
| `max_errors` | 0 | 0 | unset |
| `min_score` | 85 | 70 | unset |
| `max_unicode_dashes` | 0 | 0 | 0 |

## 3. Level resolution

The mapping relies on this precedence for the level of one checked rule. It is a requirement on the config resolver (`slopvac-8l4.4.2`).

1. The highest layer that names the rule or its category wins. The layers are the style layer, the project config, and then each matching override block in file order.
2. Within one layer, a `rules` entry beats a `categories` entry.
3. A `rules` entry at `off` holds against every `categories` entry. Only a `rules` entry in a higher layer revives the rule.
4. A winning category level rises to the merged `minimum_severity` of the category. `off` sets no floor.
5. A rule that no layer names reports at the level of its definition.

2.x resolved the same cases in a different order. A profile category level did not apply to an advisory rule, but an authored category level did. A profile per-rule default beat an authored category level. The expansion in section 4 closes those gaps. The resolver needs no tier.

## 4. Preserve behavior

`slopvac migrate --preserve-behavior` writes a 3.0 config that reproduces the 2.x gates. Without the flag, `migrate` writes only the profile name, the default 3.0 styles apply, and the golden suite policy mode reviews the deltas (`slopvac-8l4.2.7`). The expansion has these steps, and the tests in `tests/contract/test_profile_mapping.py` run each as a scenario against the 2.x engine.

- **E1.** Set `profile` to the 2.x profile and `styles` to `["core:legacy-<profile>"]`. Copy the authored `categories` and `rules`.
- **E2.** For each category that a layer authors, write into that layer a `rules` entry for each profile default of that category that the layer does not set itself. The value is the default for the profile in force in that layer. In 2.x a per-rule default beat an authored category level.
- **E3.** The 3.0 config forbids `styles` in an override, and it refuses two override blocks with the same `files`. For each override i that sets `profile`, fold the profile switch into block i, at the place of block i. The switch holds:
  - the category dials of the target style, minus any field the top level authors, `max_per_100_words = "none"` for each category that the target style leaves without a budget while another style gives it one (this clears a budget that the base style or an earlier switch set), and the category's own 2.x weight for each category that the target style leaves without a weight while another style gives it one;
  - one `rules` entry for each rule that any legacy style or the top level names, set to the state of the target profile;
  - for a rule that the top level authors, the authored level when 2.x does not ignore it under the target profile, and the target state otherwise;
  - no entry for an advisory rule in a category that the top level authors;
  - no entry for a checked rule in a category that block i or a restated block authors, unless the target profile excludes the rule or gives it a default, because 2.x applied the authored category level to that rule;
  - no entry for a checked rule in a category that a moved block authors, unless the target style names the rule.

  Inside block i, the authored entries of the block beat the switch entries. Each earlier override j that the containment forest relates to block i changes as follows:
  - j contains i (every file of i matches j): restate the authored categories and rules of j in block i, under the keys that block i authors. This is exact, because 2.x applied j to every file of i.
  - j lies inside i: move block j to directly after block i and expand it under the target profile. Drop from it every setting that block i, a block after j that contains i, or a block that j gave way to in an earlier move also sets. A block can move more than once, and each move keeps what the earlier ones dropped. Then restate their `rules` entries in each category that block j still levels, because a category entry in a later block beats a rule entry in an earlier one. The block that won in 2.x then still wins. The order of the other blocks that relate to j stays.
  - j and i are disjoint: no change.

  A second profile override then resets everything the first one set.

  Limit: `migrate` refuses a category entry that applies above a profile switch, with `migrate-output-invalid` and exit 2, before it writes anything. For a block i that sets `profile`, these entries are refused:
  - any category that 3.0 keeps, even an empty entry, in block i, in an earlier block that contains i or lies inside i, or in a later block whose files meet those of i;
  - any named category at the top level, even an empty entry, with any profile switch.

  E5 gives such a category a level, and a `rules` entry at `off` in a lower layer holds against it (section 3, rule 3). The migrated config would then not keep the 2.x levels. A follow-up will support these layouts.
- **E4.** Handle an authored `rules` entry that 2.x ignored. A file matches a set of override blocks, and 2.x decides from the final profile and category levels of that set. The expansion lists the sets that the block globs allow, using the containment of the globs. It drops an entry that is ignored in every set it can see, with a notice. An entry that is ignored in some sets stays, and a guard block at the end of the overrides sets the rule to `off` for the files of each such set. The guard `files` list uses a negated pattern for each block nested inside the region. When a guard has the same `files` as a block, its `off` entries merge into the last such block instead, because 3.0 refuses two blocks with the same `files`. The merge happens only when no later block whose `files` contain or equal the guard's sets a guarded rule or the `severity` of its category, because either would outrank the merged `off`. Otherwise the guard stays its own block at the end. Known limit: that guard repeats the `files` of the block, so the config does not load, and `migrate` stops with `migrate-output-invalid` before it writes anything. 2.x ignored an entry for a judgement rule, a tier-excluded rule, or a rule in a category that is off in the final levels of the set. `migrate` always drops a judgement entry.
- **E5.** 2.x credited the whole category as authored when a layer wrote any field of it. An advisory rule then took the category level. When an authored category has no `severity`, write the severity of the profile in force.
- **E6.** `none` is the 3.0 spelling that clears a budget. A higher layer cannot unset a field by omission, and 2.x had no such spelling. The style and config schemas accept it, and the resolver treats it as "no budget". The category weights that E3 writes come from the `[weights]` table of `crates/slopvac-migrate/data/legacy/catalogue.toml`, which `crates/slopvac-migrate/tests/fixtures/generate.py` generates from the 2.x ruleset. Under the E3 limit, the weight step takes no effect: each category whose weight it restores is `off` in the relaxed style, and the limit refuses every layer that could turn it on. It applies again once a follow-up supports those layouts.

Override glob grammar. `migrate --preserve-behavior` accepts one pattern per block, in one of two forms: an anchored literal path such as `docs/api`, or a tree such as `docs/**`. Gitignore matches a literal path and everything below it, and a tree matches the descendants only, so `docs/api` holds `docs/api/**`. A segment holds no wildcard, `!`, `#`, `.` or `..`, and the pattern contains a slash.

The trees form a containment forest: a region is a node minus its children, plus the root region of files that no block matches. A project with n blocks has n + 1 regions at most. Any other pattern, a block with two or more patterns, or a negated pattern stops the migration with an error that names the block.

Limit for a word blocklist. `--preserve-behavior` refuses two layouts with `migrate-output-invalid`, exit 2 and nothing written, because a style cannot hold their 2.x levels. First, a `vocabulary.path` that only an override sets, with none at the top level: the companion applies to every file, and a file outside the override would then report `vocabulary-no-blocklist`, which 2.x never did. Second, a top-level blocklist together with any profile switch in an override, even to the same profile: a switch block restates the target profile's category levels, and those can override the companion style's rule levels (an explicit `off` holds). So `--preserve-behavior` refuses every profile switch when a blocklist is set. A follow-up will support these layouts.

Known limit. A block without `profile` that authors a category takes its rule defaults from the top-level profile. When the block matches a file that a profile override also matches, three defaults can differ from 2.x: `orwell.compound-preposition`, `ai-tells-structure.definitional-negation-pair` and `ai-tells-structure.negative-guarantee-core`.

The reference for E1 to E6 is `tests/contract/preserve_expansion.py`. Its glob handling is three pure functions (`parse_glob`, `relate`, `build_regions`) over that forest. `slopvac-migrate` (`slopvac-8l4.16.1`) ports them first.

## 5. Tests

| ID | Case | Expect |
| --- | --- | --- |
| M1 | Resolve every rule, checked and judgement, under each legacy style. | The level equals the 2.x engine state. |
| M2 | Compare category budgets and weights. | They equal the 2.x resolved config. |
| M3 | Compare thresholds and shift. | They equal the 2.x values, and the shift is 0. |
| M4 | Validate each style against `style.schema.json`. | No errors. |
| M5 | Run `profile_mapping.py --check` on current, stale and missing files. | Exit 0, then exit 1 with the file name and no rewrite. |
| M6 | Select the review checklist for each genre and profile. | It equals the 2.x selection. |
| M7 | Expand each scenario config and resolve it for each sample file. | Levels, budgets and weights equal the 2.x engine. The scenarios cover a profile override, two profile overrides, and authored category, floor, rule and `off` settings. |

The reference resolver and expansion are in `tests/contract/preserve_expansion.py`. The real resolver and `migrate` replace them and keep the same scenarios. M7 also covers the glob grammar, the region count for many blocks, and the generated guard lists against the gitignore matcher that 2.x used.
