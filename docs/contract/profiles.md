# Slopvac 3.0 profile and tier mapping

Status: contract for 3.0. Bead `slopvac-8l4.2.10`. Plan: [slopvac-3.md](../design/slopvac-3.md). Config: `slopvac-8l4.2.5`. Packs and styles: [packs.md](packs.md). Compatibility matrix: [compat/](compat/).

A 2.x profile cannot be a threshold plus a severity shift. `profiles.py` sets a severity, a density budget and a weight for each category. It also sets per-rule defaults, and each rule YAML file carries a `tiers` entry per profile. The dispositions are not monotonic. `orwell-voice` is a warning at strict and an error at normal, and `meta` is an error at every profile. 3.0 removes `tiers` and gives a profile two jobs: gate thresholds and a severity shift. This document says where the rest goes.

## 1. Mapping

| 2.x | 3.0 |
| --- | --- |
| Profile name in `profile` | The same name. The 3.0 profile sets the thresholds in section 2. Its `severity_shift` is 0. |
| Category severity, budget and weight in `profile_defaults` | The `categories` table of the style `core:legacy-<profile>`. |
| Per-rule defaults in `profile_rule_defaults` | A `rules` entry in that style. |
| Rule `tiers`: `enforced` | No entry. The rule reports at its level. |
| Rule `tiers`: `advisory` | A `rules` entry at `suggestion` when the category level is higher. |
| Rule `tiers`: `excluded` | A `rules` entry at `off`, always, even inside a category that is already off. |
| Judgement rule `tiers` | A `rules` entry for every judgement rule: `enforced` is `error`, `advisory` is `suggestion`, `excluded` is `off`. |
| `thresholds` of the profile | The profile thresholds in section 2. |
| Genre to profile (`genres.py`) | The `profile` field of the genre file (packs.md section 4). |

The styles are generated by `scripts/contract/profile_mapping.py` from the 2.x engine and live in [`compat/profiles/`](compat/profiles/). They cover the whole catalogue: the checked rules and the judgement rules. The numbers per profile are in [`compat/profiles/mapping.json`](compat/profiles/mapping.json), with the per-rule defaults of each profile.

### Judgement rules

A judgement rule produces no finding. In 2.x its tier decided whether the review checklist lists it and whether a failure blocks the verdict. Its category level and every `[rules]` entry were ignored. The level of a judgement rule in 3.0 is the review level: `error` blocks the review verdict, `suggestion` reports without blocking, and `off` skips the rule. Only a `rules` entry sets it. A `categories` entry does not.

The checklist for a genre lists the judgement rules whose category recommends the genre and whose level is not `off`. This equals the 2.x selection at every profile.

## 2. Thresholds

A 3.0 profile sets these thresholds, which equal the 2.x values. An absent threshold is unset and its gate does not run.

| Threshold | strict | normal | relaxed |
| --- | --- | --- | --- |
| `max_total_per_100_words` | 1.5 | 3.0 | 8.0 |
| `max_errors` | 0 | 0 | unset |
| `min_score` | 85 | 70 | unset |
| `max_unicode_dashes` | 0 | 0 | 0 |

## 3. Level resolution

The mapping relies on this precedence for the level of one checked rule. It is a requirement on the config resolver (`slopvac-8l4.4.2`).

1. The highest layer that names the rule or its category wins. The layers are the style layer, the project config, and then each matching override block in file order.
2. Within one layer, a `rules` entry beats a `categories` entry.
3. A `rules` entry at `off` holds against every `categories` entry. Only a `rules` entry in a higher layer revives the rule.
4. A winning category level rises to the merged `minimum_severity` of the category. `off` sets no floor.
5. A rule that no layer names reports at the level of its definition.

2.x resolved the same cases in a different order. A profile category level did not apply to an advisory rule, but an authored category level did. A profile per-rule default beat an authored category level. The expansion in section 4 closes those gaps. The resolver needs no tier.

## 4. Preserve behavior

`slopvac migrate --preserve-behavior` writes a 3.0 config that reproduces the 2.x gates. Without the flag, `migrate` writes only the profile name, the default 3.0 styles apply, and the golden suite policy mode reviews the deltas (`slopvac-8l4.2.7`). The expansion has these steps, and the tests in `tests/contract/test_profile_mapping.py` run each as a scenario against the 2.x engine.

- **E1.** Set `profile` to the 2.x profile and `styles` to `["core:legacy-<profile>"]`. Copy the authored `categories` and `rules`.
- **E2.** For each category that a layer authors, write into that layer a `rules` entry for each profile default of that category that the layer does not set itself. The value is the default for the profile in force in that layer. In 2.x a per-rule default beat an authored category level.
- **E3.** The 3.0 config forbids `styles` in an override. For each override that sets `profile`, insert before all override blocks one block with the same `files`. It holds:
  - the category dials of the target style, minus any field the top level authors, and `max_per_100_words = "none"` for each category that the target style leaves without a budget while another style gives it one (this clears a budget that the base style or an earlier switch set);
  - one `rules` entry for each rule that any legacy style or the top level names, set to the state of the target profile;
  - for a rule that the top level authors, the authored level when 2.x does not ignore it under the target profile, and the target state otherwise;
  - no entry for an advisory rule in a category that the top level authors.

  A second profile override then resets everything the first one set.
- **E4.** Handle an authored `rules` entry that 2.x ignored. A file matches a set of override blocks, and 2.x decides from the final profile and category levels of that set. The expansion lists the sets that the block globs allow, using the containment of the globs. It drops an entry that is ignored in every set it can see, with a notice. An entry that is ignored in some sets stays, and a guard block at the end of the overrides sets the rule to `off` for the files of each such set. The guard `files` list uses a negated pattern for each block nested inside the region. 2.x ignored an entry for a judgement rule, a tier-excluded rule, or a rule in a category that is off in the final levels of the set. `migrate` always drops a judgement entry.
- **E5.** 2.x credited the whole category as authored when a layer wrote any field of it. An advisory rule then took the category level. When an authored category has no `severity`, write the severity of the profile in force.
- **E6.** `none` is the 3.0 spelling that clears a budget. A higher layer cannot unset a field by omission, and 2.x had no such spelling. The style and config schemas accept it, and the resolver treats it as "no budget".

Known limits. When the globs of two override blocks overlap in a way the expansion cannot state, `migrate --preserve-behavior` stops with an error that names the blocks. Examples are a pattern with a wildcard other than a trailing `**`, a block with more than one pattern, and a negated pattern. A block without `profile` that authors a category takes its rule defaults from the top-level profile. When the block matches a file that a profile override also matches, three defaults can differ from 2.x: `orwell.compound-preposition`, `ai-tells-structure.definitional-negation-pair` and `ai-tells-structure.negative-guarantee-core`.

## 5. Tests

| ID | Case | Expect |
| --- | --- | --- |
| M1 | Resolve every rule, checked and judgement, under each legacy style. | The level equals the 2.x engine state. |
| M2 | Compare category budgets and weights. | They equal the 2.x resolved config. |
| M3 | Compare thresholds and shift. | They equal the 2.x values, and the shift is 0. |
| M4 | Validate each style against `style.schema.json`. | No errors. |
| M5 | Run `profile_mapping.py --check` on current, stale and missing files. | Exit 0, then exit 1 with the file name and no rewrite. |
| M6 | Select the review checklist for each genre and profile. | It equals the 2.x selection. |
| M7 | Expand each scenario config and resolve it for each sample file. | Levels, budgets and weights equal the 2.x engine. The scenarios cover a profile override, two profile overrides, and authored category, floor, rule and `off` settings. |

The reference resolver and expansion are in `tests/contract/preserve_expansion.py`. The real resolver and `migrate` replace them and keep the same scenarios.
