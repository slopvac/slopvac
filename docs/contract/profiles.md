# Slopvac 3.0 profile and tier mapping

Status: contract for 3.0. Bead `slopvac-8l4.2.10`. Plan: [slopvac-3.md](../design/slopvac-3.md). Config: `slopvac-8l4.2.5`. Packs and styles: [packs.md](packs.md). Compatibility matrix: [compat/](compat/).

A 2.x profile cannot be a threshold plus a severity shift. `profiles.py` sets a severity, a density budget and a weight for each category. It also sets per-rule defaults, and each rule YAML file carries a `tiers` entry per profile. The dispositions are not monotonic. `orwell-voice` is a warning at strict and an error at normal, and `meta` is an error at every profile. 3.0 removes `tiers` and gives a profile two jobs: gate thresholds and a severity shift. This document says where the rest goes.

## 1. Mapping

| 2.x | 3.0 |
| --- | --- |
| Profile name in `profile` | The same name. The 3.0 profile sets the thresholds in section 2. Its `severity_shift` is 0. |
| Category severity, budget and weight in `profile_defaults` | The `categories` table of the style `core:legacy-<profile>`. |
| Per-rule defaults in `profile_rule_defaults` | A `rules` entry in that style. |
| Rule `tiers`: `enforced` | No entry. The rule reports at its level. |
| Rule `tiers`: `advisory` | A `rules` entry at `suggestion` when the category level is higher. |
| Rule `tiers`: `excluded` | A `rules` entry at `off`. |
| `thresholds` of the profile | The profile thresholds in section 2. |
| Genre to profile (`genres.py`) | The `profile` field of the genre file (packs.md section 4). |

The styles are generated by `scripts/contract/profile_mapping.py` from the 2.x engine and live in [`compat/profiles/`](compat/profiles/). A rule entry exists only where a category level alone would give the rule the wrong state. The numbers per profile are in [`compat/profiles/mapping.json`](compat/profiles/mapping.json).

## 2. Thresholds

A 3.0 profile sets these thresholds, which equal the 2.x values. An absent threshold is unset and its gate does not run.

| Threshold | strict | normal | relaxed |
| --- | --- | --- | --- |
| `max_total_per_100_words` | 1.5 | 3.0 | 8.0 |
| `max_errors` | 0 | 0 | unset |
| `min_score` | 85 | 70 | unset |
| `max_unicode_dashes` | 0 | 0 | 0 |

## 3. Preserve behavior

`slopvac migrate --preserve-behavior` maps a 2.x `profile = "<name>"` to `profile = "<name>"` plus `styles = ["core:legacy-<name>"]`. The run then reports each rule at the 2.x state and applies the 2.x budgets, weights and thresholds. A project override in `[categories]` or `[rules]` stays final, as in 2.x.

Two resolution differences remain, and the generator accounts for both:

- 2.x ignored a category level that a profile supplied when the rule was advisory. In 3.0 a style category level sets every rule in the category, so each advisory rule gets its own entry.
- 2.x let a human-written category level win over the advisory demotion. 3.0 treats every `categories` entry in the project config as final, so this case needs no entry.

Without `--preserve-behavior`, `migrate` writes only the profile name. The default 3.0 styles then apply, and their deltas against 2.x are reviewed in the golden suite policy mode (`slopvac-8l4.2.7`).

## 4. Tests

| ID | Case | Expect |
| --- | --- | --- |
| M1 | Resolve every checked rule under each legacy style with the reference resolver. | The state equals the 2.x engine state (`is_active` and `severity_for`). |
| M2 | Compare category budgets and weights. | They equal the 2.x resolved config. |
| M3 | Compare thresholds and shift. | They equal the 2.x values, and the shift is 0. |
| M4 | Validate each style against `style.schema.json`. | No errors. |
| M5 | Regenerate the files. | They equal the committed files. |

The tests are in `tests/contract/test_profile_mapping.py`. The reference resolver there applies the rule that a rule entry is final, then the category level, then the level of the rule definition. The engine epic replaces it with the real resolver and keeps the same cases.
