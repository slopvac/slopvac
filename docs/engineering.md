# Engineering standards

This page lists the requirements every change to the Rust code in `crates/` must meet. Reviewers, human and agent, check a change against it.

- A rule marked "target: after `<bead>`" is not met by the whole code base yet. New code follows it. Existing code moves when the named bead lands.
- A rule without a marker holds now.
- To deviate from a rule, follow [How to request a departure](#how-to-request-a-departure).

Each rule gives a source. A repository source is a link. A source written as skill `<id>` is a coding-agent standard, not a repository file. Skill ids refer to the team's OpenCode plugin standards.

## Errors

- Libraries define one `thiserror` enum per module and a `Result` alias. Derive `Error`, do not write `Display` by hand, and size each enum to its operation. Exception: a `Display` that must sanitize text. Why: callers match on variants, and the derive keeps messages and sources in sync. Target: after `slopvac-8l4.3.50` (engine) and `slopvac-8l4.2.32` (contract and plugins), because `slopvac-engine`, `slopvac-plugins` and `slopvac-rules` still use error structs or hand-written `Display`. Sources: [architecture record, decision 10](design/0001-slopvac-3-architecture.md#10-error-and-diagnostic-rendering-thiserror-anyhow-annotate-snippets), skill `lang-rust-libraries`.
- The binary reports failures through the typed `CliError`. Each error carries a stable kebab-case code. Text output renders `error[<code>]: <message>`. Why: codes are part of the interface and message text is not. Sources: [`errors.rs`](../crates/slopvac/src/errors.rs), [policies, error codes](contract/policies.md#35-error-codes).
- Take every code from one registry. No free-string code at a call site. Target: after `slopvac-8l4.21.6`.
- Never reuse a code and never change its meaning. A retired code stays in the generated docs, marked retired. Source: [policies, error codes](contract/policies.md#35-error-codes).
- Use only exit codes 0 (pass), 1 (a gate failed) and 2 (run incomplete). Treat exit 2 as incomplete. A panic under `panic = "abort"` exits with another code, so keep panics out of library code. Source: [policies, error codes](contract/policies.md#35-error-codes).

## Logging and output

- Every user-facing message comes from one message registry. This covers CLI output, error and diagnostic messages, notices, help text, and language server and report text. No literal message at a call site. Three exemptions apply, per the design on `slopvac-8l4.21.6`: clap's built-in text (usage errors and section headings) stays with clap, prose on generated reference pages is exempt because the prose gate covers it, and `frontmatter-spans` takes no registry dependency because its callers wrap its errors. Each stable error code maps to a message template with named parameters. The docs generator reads the same registry. A CI check rejects bypassing literals. Why: one source keeps wording, codes and generated docs in step. Target: after `slopvac-8l4.21.6`. Source: [policies, error codes](contract/policies.md#35-error-codes).
- Apart from the three exemptions above, the message registry follows these rules, so a later move to Fluent needs no rewrite. Every message code is a valid Fluent message id. Parameters are named, never positional. All rendering goes through one function in `slopvac-messages`, never through per-variant `Display` bodies. Parameter types are plain values (strings, numbers, redacted paths), and counts are marked for later plural selection. Keep text out of code where possible, and add a test that exports the whole catalog as `.ftl` to prove compatibility. Add no Fluent dependency now. Target: after `slopvac-8l4.21.6`.
- Libraries stay silent. No `println!`, `eprintln!` or `dbg!` in a library crate. They emit `tracing` events and spans and return values. Why: the binary owns the streams. The workspace lints `print_stdout` and `print_stderr` enforce it, and the three binaries opt out with a reasoned allow. Existing violations carry a crate-level `TEMPORARY` allow, and the standards-migration beads `slopvac-8l4.12.33`, `slopvac-8l4.2.32`, `slopvac-8l4.14.26` and `slopvac-8l4.3.50` track the burn-down. Source: skill `lang-rust-libraries`.
- The binary installs one stderr subscriber, and `SLOPVAC_LOG` turns it on. Logging is off when the variable is unset, and no log file exists. Sources: [`logging.rs`](../crates/slopvac/src/logging.rs), [policies, logging](contract/policies.md#17-logging-and-redaction).
- The language server writes only protocol frames to stdout. Why: stdout is the transport. Source: [plan, Language and runtime](design/slopvac-3.md#language-and-runtime).
- Logs, panics and error chains never carry document text, matched spans, front matter values, terms, credentials or `Authorization` headers. Show paths relative to the project root, `<external>/<file name>` outside it, and `<stdin>` for stdin. Strip URL user-info before logging. Source: [policies, logging](contract/policies.md#17-logging-and-redaction).
- Escape output through `slopvac-sanitize` only. Do not write another escaper for terminal, XML, GitHub or HTML output. Why: escaping defects are injection defects. Target: after `slopvac-8l4.2.32`, because `slopvac-report` still has its own escapers. `slopvac-sanitize` already offers terminal, HTML and workflow escaping, but it has no XML-specific coverage (the XML 1.0 character rule) for the report formats. Sources: [threat model](contract/threat-model.md) (O1 to O4), [`slopvac-sanitize`](../crates/slopvac-sanitize/src/lib.rs).

## Panics and lints

- No `unwrap()` in library code. The workspace lint `unwrap_used` enforces it. Existing violations carry a crate-level `TEMPORARY` allow, and the standards-migration beads `slopvac-8l4.12.33`, `slopvac-8l4.2.32`, `slopvac-8l4.14.26` and `slopvac-8l4.3.50` track the burn-down. Source: skill `lang-rust-quality`.
- Use `expect` only for an invariant from local construction or bundled data (a regex literal, an embedded table). Mark the site `#[expect(clippy::expect_used, reason = "...")]`. Do not call `expect` on input from a file, the network, a plugin or the user. Return an error. The workspace lint `expect_used` enforces it. Existing violations carry a crate-level `TEMPORARY` allow, and the standards-migration beads `slopvac-8l4.12.33`, `slopvac-8l4.2.32`, `slopvac-8l4.14.26` and `slopvac-8l4.3.50` track the burn-down.
- Every `#[allow]` and `#[expect]` has a `reason`. Use `#[expect(..., reason = "...")]` for a local suppression, so a stale one fails. A workspace-level allow carries `reason = "..."`. A crate-level temporary allow names the burn-down bead in its reason. The workspace lint `allow_attributes_without_reason` enforces it. Existing violations carry a crate-level `TEMPORARY` allow, and the standards-migration beads `slopvac-8l4.12.33`, `slopvac-8l4.2.32`, `slopvac-8l4.14.26` and `slopvac-8l4.3.50` track the burn-down.
- Use a module-level `#![allow(dead_code, unreachable_pub, missing_docs, reason = "...")]` only in test-support modules shared across more than one test binary (for example `tests/common/mod.rs`). Give each a reason. Never use one in production code, and never mark one temporary. No lint enforces this rule, so reviewers check it.
- Never discard a `#[must_use]` result with `.ok()`. Handle or propagate it. Where ignoring is right, write `let _ = ...` with a comment, or `#[expect(clippy::let_underscore_must_use, reason = "...")]` that names why failure is harmless. Use `map_err` in a way that keeps the source error. Narrow numbers with `try_from` and return an error, never with silent saturation. Use saturating helpers only for lossless widening. Writes into a `String` cannot fail, so route them through a small per-crate infallible helper with one scoped `#[expect(clippy::let_underscore_must_use, reason = "...")]`, never a file-wide or crate-wide expect. No workspace lint enforces this rule yet, so reviewers check it. Source: skill `lang-rust-quality`.
- Set `[workspace.lints.clippy]` to `pedantic = warn`. CI denies warnings through `-D warnings`. Add these restriction and nursery lints at least: `unwrap_used`, `expect_used`, `panic`, `todo`, `unimplemented`, `dbg_macro`, `allow_attributes_without_reason`, `undocumented_unsafe_blocks` and `clone_on_ref_ptr`. Add `print_stdout` and `print_stderr` for library crates, and `indexing_slicing` and `string_slice` for parser crates. Why: a reviewer cannot check by eye what a lint can check on every build. The root `Cargo.toml` sets all of these except the parser pair. The three binaries (`slopvac`, `slopvac-schemas` and the plugin launcher) opt out of the print lints with a reasoned allow, and each parser crate opts in from its `lib.rs`, because a crate that sets `workspace = true` cannot add lints. Existing violations carry a crate-level `TEMPORARY` allow that names the burn-down bead. Source: skill `lang-rust-quality`.
- `unsafe` is forbidden. The workspace sets `unsafe_code = "forbid"`. The one exception is `slopvac-pcre2`, which wraps the PCRE2 C library: it sets `unsafe_code = "deny"` and only `src/ffi.rs` opts in. See the [approved departures](#approved-departures). Sources: [`Cargo.toml`](../Cargo.toml), [`slopvac-pcre2/Cargo.toml`](../crates/slopvac-pcre2/Cargo.toml).
- Code builds clean under the workspace lints. `cargo clippy --workspace --all-targets --all-features -- -D warnings` passes. Source: [CONTRIBUTING, Rust workspace](../CONTRIBUTING.md#rust-workspace).

## Workspace and manifests

- Declare every dependency version once under `[workspace.dependencies]` and use `dep.workspace = true` in the crate. This includes dev-dependencies, patch pins and feature sets. Target: after `slopvac-8l4.21.5`, because 15 dependency declarations are still inline in member manifests. Source: skill `lang-rust-packaging`.
- Every crate except `slopvac-pcre2` sets `[lints] workspace = true`. Every crate inherits `version`, `edition`, `rust-version` and `license` from `[workspace.package]`. Source: [`Cargo.toml`](../Cargo.toml).
- Keep the toolchain pin and the `rust-version` floor. `rust-toolchain.toml` pins the dev toolchain. `mise.toml` repeats its version, components and profile, so a global mise config does not override it. A global override file still wins. Bump both together. The quick-lint job fails when they differ. `rust-version` in `Cargo.toml` trails stable by two minor releases. Raise it only with a recorded reason. Source: [`Cargo.toml`](../Cargo.toml).
- Pin a dependency only with a comment that gives the reason. Source: [`Cargo.toml`](../Cargo.toml) (`pcre2-sys`, `saphyr-parser`).
- A new crate needs a `Cargo.lock` entry in `extra-files` of `release-please-config.json`. Run `just sync-release-please`. Source: [CONTRIBUTING, Rust workspace](../CONTRIBUTING.md#rust-workspace).

## API surface

- `lib.rs` is a thin facade. Declare modules private, mark items `pub(crate)` by default, and re-export a curated list with `pub use`. Why: every `pub` item is a promise. Target: after `slopvac-8l4.12.33` (CLI), `slopvac-8l4.3.50` (engine) and `slopvac-8l4.2.32` (contract and plugins), because `slopvac`, `slopvac-config`, `slopvac-agents`, `slopvac-plugins` and `slopvac-update` still expose many public modules. Source: skill `lang-rust-packaging`.
- No glob re-exports (`pub use x::*`). Target: after `slopvac-8l4.3.50`, because `slopvac-rules` still re-exports `slopvac-model` with a glob. Source: skill `lang-rust-packaging`.
- Public contract types are `#[non_exhaustive]` and have constructors. This covers the types in `slopvac-model` and the plugin protocol messages. Why: adding a field or variant must not break callers. Target: after `slopvac-8l4.3.50` (model) and `slopvac-8l4.2.32` (protocol).
- Every public item has docs, and every `lib.rs` opens with a one-sentence purpose. The workspace denies broken intra-doc links and warns on missing docs. Sources: [`Cargo.toml`](../Cargo.toml), [slopvac-3 plan, Generated documentation section](design/slopvac-3.md#generated-documentation).

## Dependencies and crate layout

- Dependencies point downward. A leaf crate depends on no crate above it. The `slopvac` binary wires the libraries together. Dev-dependency cycles are also not allowed. Target for the existing `slopvac-migrate` to `slopvac-agents` dev cycle: after `slopvac-8l4.14.26`. Source: skill `lang-rust-packaging`.
- `slopvac-agents` depends on `slopvac-sanitize` to escape the project's `.slopvac/PRIME.md` notes for the terminal before `prime` prints them, and on `slopvac-fs` for the confined, capped read. Both are leaf crates below it, and neither adds a new layer. Source: [`prime.rs`](../crates/slopvac-agents/src/prime.rs).
- `slopvac-engine` depends on `slopvac-report` so the `cases` command prints its notice with the report's own text line, `notice[<code>]: <message>`, through `slopvac_report::render_notice`. That keeps one wording and one escaping path for a notice in text output. `slopvac-report` depends only on `slopvac-messages`, `slopvac-model` and `slopvac-sanitize`, and never on the engine, so the edge points downward. Source: [`render_notice`](../crates/slopvac-report/src/lib.rs), [`Cargo.toml`](../crates/slopvac-report/Cargo.toml).
- `slopvac-packs` loads the core pack and the synced packs. It reads the lock and the store from `slopvac-plugins`, so it sits above that crate. It uses `globset` to parse `provides` globs and builds each regex itself under `regex` nesting and size limits, so a hostile glob is a typed refusal and never a panic. It charges the X3 budgets while it loads: manifest and file bytes, rules, and the compiled size of each pattern as PCRE2 reports it, which stops the load before the next pattern compiles. Each pattern of a tagger is reserved and settled the same way, so a tagger stops compiling at the first pattern that crosses the budget. Every refusal has the code `rules-budget-exceeded`, and the binary registers its message catalog. A synced pack's taggers register after the core's, under the same pattern cap, and its patterns count toward the run's compiled-pattern budget. A tagger that takes the id of another tagger, or emits a tag that a core tagger emits, is refused. A plugin whose rule has the id of a core one, or whose qualified rule id another plugin supplies, is refused with `plugin-rule-id-collision`. A plugin whose category has the id of a core category, with no rule id shared, is refused with `plugin-category-id-collision`. The core ids are collected before any plugin is checked, and two plugins may share a bare rule id because plugin ids qualify them. A budget refusal names the plugin whose load crossed it. A file in a plugin directory may hold up to 2 MiB, and a larger one is refused with `rules-file-too-large`. A style file is the exception: it may hold up to 1 MiB, and a larger one is refused with `style-too-large`, before its bytes are decoded. A source that is not a directory, such as the embedded core, caps only rule and category files (2 MiB, `rules-file-too-large`) and style files (1 MiB). The byte budgets bound its other files. Nothing hands a plugin tagger or a plugin rule to the engine or the CLI yet. Source: [`synced.rs`](../crates/slopvac-packs/src/synced.rs), [`expand.rs`](../crates/slopvac-packs/src/expand.rs).
- `slopvac-schemas` generates the `schemas/v3` files from the Rust types, so it depends on the crates that own those types: `slopvac-model`, `slopvac-rules` and, for the plugin manifest, `slopvac-packs`. It also depends on `slopvac`, the CLI library crate, for the doctor report type, and on `slopvac-sanitize`, a leaf crate, so the lock `source` pattern excludes the code points that `slopvac_sanitize::is_unsafe` flags, taken from `slopvac_sanitize::unsafe_ranges` and never copied. The plugin index and the lockfile have typed models in `slopvac-plugins` (`Index` and `Lockfile`), but they are validated domain types that hand-written parsers build, not wire models, so a derive from them would not describe the documents. Schema-only helper types in this crate describe the documents instead, and the conformance corpus runs through both the reader and the schema to keep them equal. Nothing depends on `slopvac-schemas`, so no edge forms a cycle. It is the top-level generator crate: it depends on the libraries whose types it renders, and no library depends on it, so every edge points downward. `slopvac-packs` stays free of schema code beyond `schemars` attributes and schema-only helper types that the generator reads. Source: [`artifacts.rs`](../crates/slopvac-schemas/src/artifacts.rs), [`Cargo.toml`](../crates/slopvac-schemas/Cargo.toml).
- `slopvac-agents` depends on `slopvac-context` so that `claims` splits a paragraph under the same sentence budget as a lint run, through `slopvac_context::sentence_budget`, and reports an overrun as `slopvac_context::Error::SentenceLimit`. `slopvac-context` depends on none of the crates above it, so the edge points downward. Source: [`claims.rs`](../crates/slopvac-agents/src/claims.rs), [`Cargo.toml`](../crates/slopvac-agents/Cargo.toml).
- `slopvac-plugins` uses `regex` (already a workspace dependency) for one pattern, `\p{Default_Ignorable_Code_Point}`, in `collision_keys`. The crate adds no hand-maintained default-ignorable table, because `regex` supplies it. It still uses the case-fold tables of `caseless` and the normalization tables of `unicode-normalization`. The deny list in `apply/sensitive.rs` classifies from those same keys, so the fold lives in one place. Source: [`extract.rs`](../crates/slopvac-plugins/src/extract.rs), [`sensitive.rs`](../crates/slopvac-plugins/src/apply/sensitive.rs).
- `slopvac-model` owns the reserved plugin names in `reserved.rs`: `core` is the reserved id and namespace, and `slopvac` is the only first-party namespace. `slopvac-config`, `slopvac-schemas` and `slopvac-plugins` read them, so `slopvac-plugins` depends on `slopvac-model`, and the edge points downward. `slopvac_plugins::sign` re-exports them, so its public path stays the same. `schemas/v3/config.schema.json` holds a contract-owned copy of the extra-index restriction, which must stay equal to the constants. Source: [`reserved.rs`](../crates/slopvac-model/src/reserved.rs), [`sign.rs`](../crates/slopvac-plugins/src/sign.rs).
- A library may expose a clap `command()` and `run()` for the CLI to wire. The CLI relies on that pattern. Sources: [`cli.rs`](../crates/slopvac/src/cli.rs), bead `slopvac-8l4.12.13`.
- `slopvac-plugins` exposes the `plugins` group this way. The binary builds one `Runner`: directories (the plugin store in the data directory, the trust store in the state directory), the network mode, the keys, the revocation source and the config ranges. It supplies no `PluginLoader` yet, so `plugins trust` refuses with `plugins-trust-inputs-failed` and `status` reports the trust state as unknown. `list`, `status`, `sync`, `outdated`, `update` and `untrust` run on it. `search`, `pin`, `rotate` and the authoring commands report `command-not-wired` until their beads land. Source: [`cli.rs`](../crates/slopvac-plugins/src/cli.rs).
- `slopvac-migrate` lints the before and after sides through the CLI's config resolver, which the CLI passes in through the `Configure` trait. The bridge from a resolved config to engine settings stays in one place, the `slopvac` crate, and migrate never depends on the binary crate. Sources: [`migrate_lint.rs`](../crates/slopvac/src/migrate_lint.rs), [`lint.rs`](../crates/slopvac-migrate/src/lint.rs).
- Build command trees with the clap builder API (`Command`, `Arg`) only. Why: one style, trees built by each library's `command()`, and no unused proc-macro build cost. The `clap` entry in [`Cargo.toml`](../Cargo.toml) enables no `derive` feature.
- No async runtime. Use rayon for CPU work, and threads with crossbeam-channel for waiting work. `tokio` and `async-std` are banned in `deny.toml`. Sources: [architecture record, decision 3](design/0001-slopvac-3-architecture.md#3-no-async-runtime), [`deny.toml`](../deny.toml).
- One cohesive theme per crate, named for the theme. Never name a crate or module `util`, `common`, `misc`, `helpers` or `shared`. Open the `lib.rs` docs with a one-sentence purpose. Source: skill `lang-rust-packaging`.
- A helper with one user stays in that crate. Create a shared crate only when at least two dependants share its theme. Source: skill `quality-code-policy`.
- A shared crate holds no slopvac domain types, depends only on `std` and vetted crates, and never depends upward. Source: skill `lang-rust-packaging`.

### Where shared helpers live

| Concern | Home |

Target: after `slopvac-8l4.21.2`. Until then, do not add another copy. |
| Regex escaping | `slopvac-text`. Target: after `slopvac-8l4.3.50`, because `slopvac-rules` and `slopvac-context` each keep a local escaper. |

Index lines and columns only through its public `LineIndex` API and add no slopvac-specific code to it. Why: the audit found five copies of root-relative display, four path normalizers, eight atomic writers and nine capped readers, each with different edge cases. ## Configuration and paths

- Resolve config through the layer stack in `slopvac-config`. Every value keeps its file, line and column. Sources: [architecture record, decision 6](design/0001-slopvac-3-architecture.md#6-hand-rolled-config-layer-stack-with-provenance), [decision 20](design/0001-slopvac-3-architecture.md#20-config-precedence-nearest-config-and-front-matter).
- Write only to the per-user cache directory, the project's `.slopvac/` directory and paths the user names. Source: [policies, data written to disk](contract/policies.md#18-data-written-to-disk).
- Use no prompt in any code path. Agents and CI cannot answer one. Source: [architecture record, decision 9](design/0001-slopvac-3-architecture.md#9-oci-artifacts-minisign-and-mise-style-trust).
- Write no native Windows code in 3.0. Do not add `cfg(windows)` branches or Windows dependencies. Windows users run the Linux build under WSL. Target for the existing Windows code: removal after `slopvac-8l4.21.5`. Source: [architecture record, decision 26](design/0001-slopvac-3-architecture.md#26-no-native-windows-in-30).

## User-facing text

- Messages, help and docs never name internal IDs, bead IDs, PR numbers or development history. Why: users cannot act on them, and they go stale. Source: the prose rules from `slopvac prime write`. This page is exempt because it is a contributor document.
- Message text may change in any release. Codes, rule IDs and exit codes are the interface. Source: [policies, error codes](contract/policies.md#35-error-codes).

## Testing

Detail and tool choice: [`testing-rust.md`](testing-rust.md).

- Run tests with `cargo nextest run` and run doctests with `cargo test --doc`. nextest skips doctests. Source: [testing, Choose the tool](testing-rust.md#choose-the-tool).
- Write one behavior per test, through the public interface. Work out expected values apart from the code under test. Sources: [testing, Rules](testing-rust.md#rules), skill `quality-testing`.
- Do not mirror the implementation. A refactor leaves tests unchanged. Delete the tests of removed behavior. Do not write a test that only checks code is gone. Source: skill `quality-testing`.
- Parametrize cases that differ only in data with rstest and `#[case::name]`. Source: [testing, Rules](testing-rust.md#rules).
- Use proptest for an invariant over any input (parsers, config merge, span arithmetic). Commit the `.proptest-regressions` files. Source: [testing, Property tests](testing-rust.md#property-tests).
- Review insta snapshots and never auto-accept them. CI fails on a missing or changed snapshot. Source: [testing, Snapshots](testing-rust.md#snapshots).
- Test the CLI with snapbox against the built binary. Target: after `slopvac-8l4.14.26`, because some tests still use `assert_cmd`. Source: [testing, Choose the tool](testing-rust.md#choose-the-tool).
- No `#[ignore]` without a CI job that runs ignored tests. Why: an ignored test that never runs proves nothing. Target: after `slopvac-8l4.14.26`, which adds the job.
- Fake only at boundaries the project owns (network, process, clock, filesystem). Do not mock a type you do not own. Source: skill `quality-testing`.
- Never weaken an assertion or edit an expected value just to pass. Source: [testing, Rules](testing-rust.md#rules).

## Supply chain and documentation

- `cargo deny check` passes. Licences are permissive only. Never add `CC-BY-SA-4.0` to the global allow list. Scope it to the crate that embeds the model. Sources: [`deny.toml`](../deny.toml), [CONTRIBUTING, Rust checks](../CONTRIBUTING.md#rust-checks).
- `cargo shear`, `cargo sort` and `typos` pass. No unused dependency, sorted manifests. Source: [CONTRIBUTING, Rust checks](../CONTRIBUTING.md#rust-checks).
- `mise.lock` pins and checksums only the CI-installed tools, `taplo` and `ast-grep`, on purpose. The aqua registry carries no checksum for either, so the lock file is the check, and the CI install steps set `MISE_LOCKED=1` so a missing or wrong entry fails the install. Rules:
  - Use mise 2026.11.6 or later. The lock file is version 4, and mise 2026.10.19 warns that it cannot read it and ignores it.
  - After you change a pin in `mise.toml`, run `mise lock taplo ast-grep --platform linux-x64,linux-arm64,macos-arm64,macos-x64` and commit the result.
  - A plain `mise install` of any other tool appends entries for every tool in `mise.toml` to `mise.lock`. Run `git restore mise.lock` (or drop those hunks) before you commit.
  - Trust on first use: `mise lock` records the checksum of the file it downloads, because upstream publishes no checksum or signature for these assets. Later installs verify against the committed value, so review a checksum change in `mise.lock` like any other pin change.

  Source: [`mise.lock`](../mise.lock), [`lint.yml`](../.github/workflows/lint.yml).
- Before you push, run each Rust check:
  - `cargo fmt --all --check`
  - `cargo clippy --workspace --all-targets --all-features -- -D warnings`
  - `cargo nextest run --workspace`
  - `cargo test --doc --workspace`
  - `prek run --all-files`, which covers the manifest and spelling hooks but not clippy, nextest or doctests.

  Source: [CONTRIBUTING, Rust workspace](../CONTRIBUTING.md#rust-workspace) and [Rust checks](../CONTRIBUTING.md#rust-checks).

The `Reported` value carries the code of the failure, and it is a catalog of its own, so a lookup through `Catalog` (direct, generic or trait object) reports that code. Alternative: keep the typed error as the source, rejected because the chain would print the path. Alternative: scan the text for absolute paths, rejected because a scan misses what it does not match. Residual risk: a caller loses the typed cause and the detail of a withheld variant, and a new path-bearing variant must be added to `cause.rs` or it renders as withheld, which is safe. Scope: `cause.rs` and the `Failed` and `Store` variants. Revisit when the library errors redact their own paths. | [`cause.rs`](../crates/slopvac-plugins/src/cause.rs), [policies, logging](contract/policies.md#17-logging-and-redaction) |

## How to request a departure

1. Open the pull request that needs the departure. State the rule and the files it affects.
2. In the pull request description, record the reason, the alternatives you considered, the residual risk and a revisit trigger (an event or date at which to reassess).
3. Add a row to [Approved departures](#approved-departures) in the same pull request, with the same four items and a source.
4. A reviewer rejects a departure that is not recorded in both places.

## Review checklist

- [ ] Library errors use a `thiserror` enum per module and a `Result` alias (target).
